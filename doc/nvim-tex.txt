==============================================================================
1. INTRODUCTION                                         *nvim-tex-introduction*

nvim-tex is a LaTeX plugin for Neovim. It takes its interface from VimTeX but
is written from scratch in Lua, with two deliberate restrictions:

  - Neovim only. There is no Vim compatibility layer and no Vimscript.
  - Structure comes from tree-sitter, language intelligence from the LSP.
    The plugin has no LaTeX parser and no syntax-group heuristics of its own.

What the plugin itself provides is the part neither tree-sitter nor texlab
covers: driving `latexmk`, the PDF viewer, SyncTeX in both directions, and the
quickfix list.

==============================================================================
2. REQUIREMENTS                                         *nvim-tex-requirements*

Required:
  - Neovim 0.10 or newer (0.11+ recommended)
  - The `latex` tree-sitter parser: `:TSInstall latex`
  - `latexmk`, which ships with TeX Live and MiKTeX

Optional but recommended:
  - `texlab` for completion, diagnostics, references and renaming
  - A SyncTeX capable PDF viewer: zathura, sioyek, okular or Skim
  - `dbus-send` for forward search into a running zathura
  - `texdoc` for the |K| mapping
  - `curl` for |:TexCite|

Run `:checkhealth nvim-tex` to see what is available.

3. INSTALLATION                                         *nvim-tex-installation*

Calling `setup` is optional. The defaults apply as soon as the plugin is
loaded; call |nvim-tex-setup()| only to change them.

lazy.nvim: >lua

    {
      'leissa/nvim-tex',
      ft = { 'tex', 'plaintex', 'latex' },
      opts = {},
    }
<
`opts = {}` only exists to make lazy.nvim call `setup`.

`vim.pack` (Neovim 0.12+): >lua

    vim.pack.add({ 'https://github.com/leissa/nvim-tex' })
<
mini.deps: >lua

    MiniDeps.add({ source = 'leissa/nvim-tex' })
<
packer.nvim: >lua

    use({ 'leissa/nvim-tex' })
<
paq-nvim: >lua

    require('paq')({ 'leissa/nvim-tex' })
<
vim-plug: >vim

    Plug 'leissa/nvim-tex'
<
Native |packages|: >sh

    git clone https://github.com/leissa/nvim-tex \
      ~/.local/share/nvim/site/pack/plugins/start/nvim-tex
<
Run `:helptags ALL` afterwards if your plugin manager does not generate help
tags for you.

4. CONFIGURATION                                       *nvim-tex-configuration*

                                                            *nvim-tex-setup()*
>lua
    require('nvim-tex').setup({
      compiler = {
        latexmk = {
          continuous = true,
          out_dir = 'build',
        },
      },
      view = { method = 'zathura' },

5. MAPPINGS                                                 *nvim-tex-mappings*

All mappings are buffer-local and are created when the plugin attaches to a
LaTeX buffer. Groups can be switched off individually: >lua

    require('nvim-tex').setup({
      mappings = {
        enabled = true,        -- all mappings
        prefix = '<localleader>',
        motions = true,        -- ]] [[ ]m [n ...
        text_objects = true,   -- ae ie ac ic ...
        surround = true,       -- dse cse tss <F6> ...
        doc_package = true,    -- K
      },
    })
<
The insert mode math mappings are a group of their own, switched off with
`imaps = { enabled = false }`. See |nvim-tex-imaps|.

Everything is also available as a command (|nvim-tex-commands|), so a
different key layout is a matter of mapping those instead.

  <localleader>r      reverse search                                 `n`

  <localleader>L      compile the operated text / selection         `nx`
  <localleader>S      compile once (single shot)                     `n`
  <localleader>k      stop this compilation                          `n`
  <localleader>K      stop all compilations                          `n`
  <localleader>e      open the quickfix list                         `n`
  <localleader>E      cycle the quickfix severity level              `n`
  <localleader>o      show the raw compiler output                   `n`
  <localleader>g      compilation status                             `n`
  <localleader>G      compilation status of all projects             `n`
  <localleader>c      clean auxiliary files                          `n`
  <localleader>C      clean auxiliary files and the PDF              `n`
  <localleader>x      reload nvim-tex                                `n`
  <localleader>X      forget all cached project state                `n`
  <localleader>s      toggle the main file                           `n`

                                                     *nvim-tex-context-menu*
The context menu (`<localleader>a`) acts on whatever is under the cursor: it
jumps to the `.bib` entry of a citation, to the `\label` of a reference, to
the definition of a TikZ node name, or opens the file of an `\input`. On a `\usepackage` it opens the package
documentation, and everywhere else it falls back to |vim.lsp.buf.definition()|.

MOTIONS                                                      *nvim-tex-motions*

All motions are |exclusive|, take a [count] and work in normal, visual and
operator-pending mode.

  ]]    next start of a section          [[    previous start of a section
  ][    next end of a section            []    previous end of a section
  ]m    next `\begin`                    [m    previous `\begin`
  ]M    next `\end`                      [M    previous `\end`
  ]n    next start of a math zone        [n    previous start of a math zone
  ]N    next end of a math zone          [N    previous end of a math zone
  ]r    next `\begin{frame}`             [r    previous `\begin{frame}`
  ]R    next `\end{frame}`               [R    previous `\end{frame}`
  ]/    next comment                     [/    previous comment
  ]*    next end of a comment            [*    previous end of a comment
  ];    next TikZ statement              [;    previous TikZ statement
  %     jump between `\begin` and `\end`, or between math delimiters

`%` falls back to the built-in |%| when the cursor is not on an environment
marker or a math delimiter.

------------------------------------------------------------------------------
TEXT OBJECTS                                            *nvim-tex-text-objects*

Available in visual and operator-pending mode.

  ae ie   environment, `document` excluded
  ac ic   command; `ic` is the command name without the backslash
  a$ i$   math zone (`$...$`, `\[...\]`, `equation`, `align`, ...)
  ad id   delimiters, including `\left( ... \right)`
  am im   `\item`
  aP iP   section
  a; i;   TikZ statement; `i;` leaves the `;` out, see |nvim-tex-tikz|

Examples: >

  BEFORE                       KEYS    AFTER
  \comm|and{arg}               dic     \{arg}
  \command{a|rg}               gUac    \COMMAND{ARG}
  \left( as|d \right)          cid     \left(|\right)

  \begin{x}                    die     \begin{x}
    hello world|                       \end{x}
  \end{x}
<

EDITING MAPPINGS                                       *nvim-tex-edit-mappings*

  dse   delete the surrounding environment            `n`
  dsc   delete the surrounding command                `n`
  ds$   delete the surrounding math zone              `n`
  dsd   delete the surrounding delimiter              `n`
  cse   change the surrounding environment            `n`
  csc   change the surrounding command                `n`
  cs$   change the surrounding math zone              `n`
  csd   change the surrounding delimiter              `n`
  tsf   toggle `\frac{a}{b}` <-> `a/b`               `nx`
  tsc   toggle a starred command                      `n`
  tsb   toggle the trailing `\\`                      `n`
  tss   toggle a starred environment                  `n`
  tse   toggle the environment (see `edit.env_toggle_map`)   `n`
  ts$   toggle inline <-> displayed math              `n`
  tsd   cycle delimiter modifiers forwards           `nx`
  tsD   cycle delimiter modifiers backwards          `nx`
  <F6>  surround the line / selection with an environment   `nx`
  <F7>  turn the word / selection into a command     `nxi`
  <F8>  add modifiers to the delimiters in the math zone    `n`

INSERT MODE MATH MAPPINGS                                      *nvim-tex-imaps*

VimTeX's `imaps`: a leader -- a backtick by default -- followed by a short
sequence inserts a LaTeX command. The expansion only happens inside a math
zone; in running text the typed keys are inserted unchanged, so the backtick
is still available for quotes. Whether the cursor is in math is decided from
the parse tree, which also covers a formula whose closing delimiter has not
been typed yet.

  TYPED    INSERTED        TYPED     INSERTED ~
  `a       \alpha          `D        \Delta
  `ve      \varepsilon     `8        \infty
  `.       \cdot           `jl       \rightarrow
  `0       \emptyset       `A        \forall
  #bx      \mathbf{x}      ``        ``

The full list is |:TexImaps| (or `<localleader>m`). It has three layers:
the symbols and Greek letters behind `imaps.leader`, the styles behind `#`,
which take one more character and wrap it, and the leader typed twice, which
inserts the two backticks that open a LaTeX quotation.

Everything is configuration: >lua

    require('nvim-tex').setup({
      imaps = {
        enabled = true,
        leader = '`',
        disabled = { 'H' },     -- leave `H alone
        list = { ... },         -- replaces the default list entirely
      },
    })
<
A single map is easier to add than to merge a whole list: >lua

    require('nvim-tex.imaps').add({ lhs = 'oo', rhs = '\\circ' })
<
An entry understands these keys:

`lhs`       The sequence typed after the leader. Taken literally.
`rhs`       The text to insert, or a function receiving the typed sequence
          and returning the text.
`style`     Shorthand for "read one more character and wrap it in this
          command": `style = 'mathbf'` turns `#bx` into `\mathbf{x}`.
`leader`    Overrides `imaps.leader` for this entry.
`wrapper`   Decides whether the expansion happens at all. `'math'` (the
          default) expands inside math zones and inserts the typed keys
          elsewhere, `'trivial'` always expands. A function(lhs, expand)
          may be given instead, where `expand()` produces the text.

7. THE MAIN FILE                                           *nvim-tex-main-file*

Compilation always runs on the main file of the project, never on the buffer
you happen to be editing. It is found by the first rule that applies:

  1. The buffer variable `b:tex_main`.
  2. The `main_file` option.
  3. A `% !TEX root = ...` directive in the first or last five lines.
  4. The buffer itself, if it has a `\begin{document}`. A shared preamble
     with the `\documentclass` but no document body is not a root.
  5. The main file of an already open project that `\input`s the current
     file, preferring the one of the alternate buffer. Opening a shared
     `header.tex` from `exam.tex` thus keeps `exam.tex` as the main file.
  6. A `*.tex` file with a `\begin{document}` in this or a parent directory,
     preferring one that `\input`s the current file.
     `*.latexmain` marker files are honoured as well.
  7. The current buffer, as a last resort.

`:TexToggleMain` (`<localleader>s`) switches between the detected main file
and the current buffer, which is handy while working on a single chapter.

A `% !TEX program = lualatex` directive selects the engine; see
`compiler.latexmk.engines`.

8. COMPILER                                                 *nvim-tex-compiler*

The `latexmk` backend is configured under `compiler.latexmk`: >lua

    compiler = {
      latexmk = {
        executable = 'latexmk',       -- string or list (e.g. docker exec ...)
        continuous = true,            -- `-pvc`
        options = {
          '-verbose',
          '-file-line-error',
          '-synctex=1',
          '-interaction=nonstopmode',
        },
        aux_dir = '',                 -- string or function(file_info)
        out_dir = '',
        clean_ext = '',               -- extra extensions for :TexClean
        hooks = {},                   -- functions called per output line
        engines = { ['_'] = '-pdf', lualatex = '-lualatex', ... },
      },
    }
<
`continuous` is the important one. With it, `:TexCompile` starts
`latexmk -pvc` and the document is rebuilt whenever a file changes; the
command toggles, so pressing `<localleader>l` again stops it. Without it,
every invocation is a single run.

Relative `aux_dir` and `out_dir` are resolved against the directory of the
main file, and the directories are created if missing. An empty `aux_dir`
follows `out_dir`, as latexmk's `-auxdir` does, so the log is looked for
next to the PDF. Both may be functions
of a `file_info` table with the keys `root`, `target`, `target_basename`,
`target_name` and `jobname`. `$VIMTEX_OUTPUT_DIRECTORY` and
`$NVIM_TEX_OUTPUT_DIRECTORY` take priority over both.

Compilations are stopped when Neovim exits, so no `latexmk -pvc` is left
behind.

`compiler.latexmk.options` is replaced wholesale when you set it, not merged,
because the defaults are only useful as a complete set.

TECTONIC                                           *nvim-tex-compiler-tectonic*

Set `compiler.method = 'tectonic'` to build with Tectonic instead: >lua

    compiler = {
      method = 'tectonic',
      tectonic = {
        executable = 'tectonic',
        options = { '--synctex', '--keep-logs' },
        out_dir = '',                 -- string or function(file_info)
        clean_ext = '',
        hooks = {},
      },
    }
<
Tectonic reruns TeX and BibTeX itself, so one run gives a finished PDF. It
has no watch mode for a plain `.tex` file, though (`tectonic -X watch` needs
a `Tectonic.toml` workspace), so every compilation is a single shot and
`<localleader>l` does not start a continuous build. Set
`compiler.build_on_save = true` to rebuild on every `:write` instead.

Differences from latexmk to be aware of:
  - Tectonic has no separate aux directory; the log is written next to the
    PDF. `--keep-logs` must stay in `options`, or the quickfix list has
    nothing to read.
  - The engine is always XeTeX; a `% !TeX program` directive is ignored.
  - `:TexClean` deletes the files itself, since tectonic has no clean
    command: the log, the SyncTeX data and the intermediates that
    `--keep-intermediates` leaves behind, plus `clean_ext`. `:TexClean!`
    also removes the PDF.
  - Tectonic stops at the first error. Add `'-Z', 'continue-on-errors'` to
    `options` to see all of them at once.

9. VIEWER                                                     *nvim-tex-viewer*

`view.method` selects the backend; `'auto'` takes the first of zathura,
sioyek, Skim, okular, `general` that is installed.

Forward search happens on `:TexView` and `:TexForwardSearch`. Inverse search
is pushed by the viewer: nvim-tex starts a |--listen| server on demand and
passes a callback command to the viewer, which ends up calling
`v:lua.NvimTexInverseSearch(line, file)` in this Neovim instance.

                                                       *nvim-tex-viewer-zathura*
zathura ~
Forward search into a running instance goes through D-Bus, so `dbus-send` is
needed; without it a second window is opened instead. Inverse search is
ctrl-click and is configured automatically.

                                                        *nvim-tex-viewer-sioyek*
sioyek ~
Uses `--reuse-window`, `--forward-search-file` and `--inverse-search`.

                                                        *nvim-tex-viewer-okular*
okular ~
Forward search uses `--unique` with a `#src:` fragment. Inverse search cannot
be set from the command line: open Settings -> Configure Okular -> Editor,
choose "Custom Text Editor" and enter >

  nvim --server <servername> --remote-expr "v:lua.NvimTexInverseSearch(%l, '%f')"
<
`:TexInfo` shows the server address to put in place of `<servername>`.

                                                           *nvim-tex-viewer-skim*
Skim (macOS) ~
Uses Skim's `displayline` helper.

                                                       *nvim-tex-viewer-general*
general ~
Runs an arbitrary command. The placeholders `@pdf`, `@tex`, `@line`, `@col`
and `@server` are substituted in `view.general.args`: >lua

    view = {
      method = 'general',
      general = {
        executable = 'evince',
        args = { '@pdf' },
      },
    }
<

                                                         *nvim-tex-viewer-float*
Floating window ~
Fragments compiled on their own, by |:TexTikzPreview| and
|:TexCompileSelected|, pop up in a floating window at the cursor instead of
the viewer, when all of these hold:

  - `view.snacks` is on (the default);
  - snacks.nvim is installed with its image support enabled
    (`image = { enabled = true }` in its setup);
  - the terminal can show images (see `:checkhealth snacks`).

The window closes when the cursor moves. Its size is bounded by snacks'
`image.doc.max_width` and `image.doc.max_height`. Otherwise, or with
`view.snacks = false`, the viewer opens as usual.

10. QUICKFIX                                                *nvim-tex-quickfix*

After every compilation the `.log` file is parsed into the quickfix list. The
parser tracks the `(file ... )` stack TeX prints, so warnings without a file
name are still attributed correctly; `max_print_line=2000` is exported to the
compiler to keep TeX from wrapping paths. BibTeX/Biber `.blg` warnings are
included when present.

>lua
    qf = {
      enabled = true,
      auto_open = true,          -- open when there is something to show
      open_on_warning = true,    -- ... even without errors
      autojump = false,          -- jump to the first entry
      auto_close = true,         -- close again on a clean run
      level = 'warning',         -- lowest severity shown; see below
      boxes = false,             -- collect over/underfull box warnings
      ignore_filters = {},       -- Lua patterns; matching messages are dropped
      height = 8,
    }
<
Errors are sorted to the top of the list, and `on input line N` is stripped
from the message text because the line number has a column of its own.

SEVERITY LEVELS                                      *nvim-tex-quickfix-levels*

A LaTeX run narrates almost everything it does, and on a document of any size
that chatter buries the handful of messages worth acting on. Instead of
dropping it, every message is classified and `qf.level` decides how much of it
reaches the quickfix list:

  `error`     Only what broke the build.
  `warning`   Plus messages saying something in the document is probably
            wrong: undefined references, missing citations, package and class
            warnings. This is the default.
  `info`      Plus TeX narrating its own work: `Package ... Info`, font
            substitutions, `Missing character`. These say nothing about
            whether the document is correct.

Over/underfull boxes sit outside this scheme: they are dropped while the log
is parsed and no level brings them back. They are a typesetting detail rather
than a defect, and in a real document they outnumber every other kind of
message put together. Set `qf.boxes = true` to collect them, and they appear
as ordinary warnings.

Otherwise nothing is lost at a lower level -- `:TexQfLevel` (or `<localleader>E`) raises
it again without recompiling, and the quickfix title reports the level in use
together with the number of messages it is hiding.

The window still opens on its own only for errors, or for warnings when
`open_on_warning` is set; a run that produced nothing but infos never
interrupts.

`ignore_filters` is the separate knob for messages you never want to see at
any level. A few famously useless ones (the hyperref PDF-string warning, the
typearea and fancyhdr layout complaints) are dropped unconditionally.

11. LSP                                                          *nvim-tex-lsp*

texlab is started per project root with |vim.lsp.start()|, which reuses an
existing client when one matches. If a client named `texlab` is already
attached to the buffer, nvim-tex leaves it alone, so an existing lspconfig
setup keeps working.

>lua
    lsp = {
      enabled = true,
      name = 'texlab',
      cmd = { 'texlab' },
      settings = { texlab = { ... } },
      config = {},               -- merged into the vim.lsp.start config
    }
<
`config` is the escape hatch for `capabilities`, `on_attach`, `handlers` and
anything else |vim.lsp.start()| accepts.

texlab's own builder and forward search are disabled by default, because
nvim-tex drives `latexmk` and the viewer itself. Completion, diagnostics,
hover, references, rename and document symbols come from texlab.

12. TREE-SITTER                                           *nvim-tex-treesitter*

Motions, text objects, the editing mappings and the table of contents all read
the `latex` parse tree. Without the parser these features are unavailable and
the plugin says so once per buffer.

>lua
    treesitter = {
      enabled = true,
      warn_missing_parser = true,
      highlight = true,          -- vim.treesitter.start()
    }
<
Neovim ships no highlight query for LaTeX; nvim-treesitter does. With one,
`highlight = true` starts tree-sitter highlighting. Without one, nvim-tex
leaves Neovim's regex `syntax/tex.vim` in charge, because starting the
highlighter would switch it off and leave the buffer without any highlighting.
`:checkhealth nvim-tex` says which of the two you get. Set
`highlight = false` if another plugin already starts the parser for you.

nvim-treesitter's injection query highlights the code in `minted`, `pycode`,
`luacode` and similar environments in its own language. nvim-tex adds
`lstlisting`, whose language is given in its options:
`\begin{lstlisting}[language=Python]`. The listings names are mapped to parser
names (`C++` is `cpp`, `sh` is `bash`); the parser has to be installed.

INDENTATION                                                  *nvim-tex-indent*

nvim-tex sets 'indentexpr' for LaTeX buffers, so `=`, `o`, `O` and typing
work structurally. The rules follow VimTeX:

  - An environment body is indented one level. `document` is not.
  - In a list environment `\item` sits one level in, and the lines that
    continue an item one level further.
  - Multi-line `{ ... }` groups, `[ ... ]` option lists, `\left ... \right`,
    `\[ ... \]` and `$$ ... $$` indent their contents one level.
  - A line starting with a closing delimiter lines up with the line that
    opened it.
  - Verbatim-like environments (`verbatim`, `lstlisting`, `minted`,
    `comment`, ...) keep whatever indentation their contents have.

The parse tree decides what counts as a delimiter, so `\{`, a brace in a
comment or the `[` of `[a, b)` are ignored. 'indentkeys' reindent the line
when a closing brace or bracket is typed, and when a line starts with `\item`,
`\bibitem`, `\end`, `\right` or `\]`.
>lua
    indent = {
      enabled = true,
      lists = { 'itemize', 'enumerate', 'description', 'thebibliography' },
      ignored_envs = { 'document' },
    }
<
In a TikZ picture, the lines that continue a statement are indented one level
further than its first line, until the `;` that ends it. See |nvim-tex-tikz|.

Both lists are replaced, not merged, when you set them. Indentation needs the
`latex` parser; without it, or with `enabled = false`, Neovim's own
`indent/tex.vim` stays in charge.

TIKZ                                                           *nvim-tex-tikz*

The parser has no TikZ grammar, so nvim-tex splits a picture into its
statements itself, reading groups, math, comments and commands off the parse
tree. A `;` in a node label, an option list or a comment never ends a
statement. A statement is

  - a path, from `\draw`, `\node` or another of `path_commands`, up to its
    `;`, over as many lines as it takes;
  - a `\foreach` loop, up to the `;` of the path it repeats or the end of its
    `{ ... }` body, whose statements are statements in turn;
  - any other command, with the braced arguments that follow it on its line:
    `\tikzset{...}`, `\pgfmathsetmacro{\x}{1}`, `\def\x{1}`.

`scope` and other environments in a picture, and `{ ... }` scopes, hold
statements of their own. `a;`/`i;` select a statement, `];`/`[;` jump
between them, and indentation continues a path until its `;`: >

  \begin{tikzpicture}
    \draw[->] (a)
      -- node[above] {$\alpha$} (b)
      -- (c);
  \end{tikzpicture}
<
>lua
    tikz = {
      environments = { 'tikzpicture', 'circuitikz' },
      path_commands = { 'path', 'draw', 'fill', 'node', ... },
    }
<
Commands are given without the backslash; the full default list is in
`lua/nvim-tex/config.lua`. Add a macro of your own that starts a path, such
as `\edge` in `\edge[red] (a) (b);`, to `path_commands`. Both lists are
replaced, not merged, when you set them.

                                                         *nvim-tex-tikz-nodes*
Node names ~

A node is named by `\node (a)`, `node (a)` on a path, `\coordinate (a)`,
`\matrix (m)` or a `name=a` option; the name may come before or after the
options and the `at (x,y)`. It is used as `(a)` or `(a.north)`, in calc
expressions such as `($(a)!0.5!(b)$)` and `fit=(a) (b)`, and as `right=of a`.
Comments do not count. Names belong to the picture they are defined in.

  - The context menu (`<localleader>a`) on a node name jumps to its
    definition.
  - |:TexTikzRename| renames the node under the cursor throughout its
    picture. A name that turns up in a node's text, `{(a) is first}`, is
    renamed along with it.
  - `<C-x><C-u>` completes the node names of the picture and the style
    names (`name/.style`, `\tikzstyle{name}`) of the buffer and the main
    file. nvim-tex sets 'completefunc' for it unless something else already
    has; `completefunc = false` leaves it alone.

                                                       *nvim-tex-tikz-preview*
Preview ~

|:TexTikzPreview| (`<localleader>p`) compiles the picture under the cursor,
cropped to its size, and opens it in the viewer, or right in the terminal
with |nvim-tex-viewer-float|. The picture is set in the
document it comes from, so it looks as it does there:

  - the preamble of the main file, from its buffer when that is open, with
    its class, fonts, packages and macros;
  - the `preview` package, which crops the page (a `standalone` class
    already does);
  - the definitions in the body before the picture, outside other pictures:
    `\newcommand`, `\def`, `\definecolor` and the other definitions, and the
    commands in `preview.commands`, such as a `\tikzset` in the `figure`
    around the picture;
  - the main document's `.aux`, so `\ref` and `\cite` resolve. A reference
    shows the number of the last full compilation. Tectonic only keeps the
    `.aux` with `--keep-intermediates` in `compiler.tectonic.options`.

It is compiled from the project root, like the main file, into the cache
directory, so the project's own output is never touched. Previewing again
recompiles, and the viewer, which stays open, reloads the PDF. Definitions in
other files included into the body before the picture are not picked up.
>lua
    tikz = {
      completefunc = true,
      preview = {
        commands = { 'tikzset', 'tikzstyle', 'pgfmathsetmacro', ... },
        aux = true,
        border = '2pt',
      },
    }
<
`preview.commands` is replaced, not merged, when you set it.

FOLDING                                                        *nvim-tex-fold*

Folding is off by default. With it on, 'foldmethod' is `expr` and
'foldexpr' is |vim.treesitter.foldexpr()|, which computes the folds from the
parse tree and keeps them up to date as you type. Neovim ships no fold query
for LaTeX, so nvim-tex installs its own; it takes precedence over the one
from nvim-treesitter.
>lua
    fold = {
      enabled = false,
      preamble = true,           -- \documentclass up to \begin{document}
      sections = true,           -- \part ... \subparagraph, nested
      envs = true,               -- multi-line environments
      ignored_envs = { 'document' },
      math = true,               -- \[ ... \] and $$ ... $$
      comments = true,           -- \begin{comment}, \iffalse ... \fi
    }
<
A section fold runs up to the line before whatever follows the section, so
the blank lines between two sections fold with the first. `ignored_envs`
matches names without a trailing `*`: `'figure'` also covers `figure*`.
The options are read whenever the folds are computed. Neovim only recomputes
them when the text changes, so after changing an option, `:edit` the buffer
to see the effect (`zx` is not enough).

Nothing else is set. 'foldlevel', 'foldtext' and friends are yours: for
example, `vim.opt.foldlevel = 99` starts with every fold open, and
`vim.opt.foldtext = ''` shows the first line of a fold highlighted.

CONCEAL                                                      *nvim-tex-conceal*

nvim-tex conceals LaTeX markup the way VimTeX's syntax does, but reads what
is what off the parse tree: `\alpha` shows as α only in math, never in text
or a comment. Nothing shows until you set 'conceallevel', which nvim-tex
leaves to you: >lua

    vim.opt_local.conceallevel = 2     -- e.g. in ftplugin/tex.lua
<
With 'conceallevel' at 0 the conceal costs nothing. 'concealcursor' decides
whether the cursor line shows the source; by default it does.

    Category            Source                  Shown as ~
    `greek`               `$\alpha, \Omega$`        `α, Ω`
    `math_symbols`        `$\leq \to \sum \{$`      `≤ → ∑ {`
    `math_fonts`          `$\mathbb{R} \mathcal{A}$` `ℝ 𝒜`
    `math_super_sub`      `$x^2 + a_{ij}$`          `x² + aᵢⱼ`
    `math_delimiters`     `$\left( x \bigr]$`       `( x ]`
    `accents`             `caf\'e na\"{i}ve`        `café naïve`
    `text_symbols`        `Stra\ss{}e \dots`        `Straße …`
    `ligatures`           `1--2 --- ``q''`          `1–2 — “q”`
    `spacing`             `a\,b \quad`              `a b  `
    `styles`              `\textbf{x} \emph{y}`     `x` in bold, `y` in italics
    `cites`               `\cite{knuth}`            `[knuth]`
    `item`                `\item`                   `•`

Each category is a key under `conceal`, true by default: >lua

    conceal = {
      enabled = true,
      greek = true,
      math_symbols = true,
      -- ...
      custom = { ['\\R'] = 'ℝ', ['\\eps'] = 'ε' },
    }
<
`custom` conceals commands of your own, in text and math alike.

A superscript or subscript is only concealed when every character in it has a
Unicode form: `x^{q}` stays as it is. A citation with a page or other
optional argument is left alone too, so the extra information stays visible.

`syntax/tex.vim` conceals on its own, and the two together garble the text.
So while nvim-tex conceals, `g:tex_conceal` is set to empty, unless you set it
yourself. The styles use the highlight groups `NvimTexBold`, `NvimTexItalic`
and `NvimTexUnderline`, which link to `@markup.strong`, `@markup.italic` and
`@markup.underline`.

13. TABLE OF CONTENTS                                            *nvim-tex-toc*

`:TexToc` opens a window listing the sectioning commands of the whole project.
`\input`, `\include` and `\subfile` are followed, so a multi-file document is
covered even when only one of its files is open. Beamer frames, `TODO`
comments and (optionally) labels are listed too.

In the TOC window: `<CR>` jumps to the entry, `r` refreshes, `q` closes.

>lua
    toc = {
      split = 'vsplit',          -- 'vsplit', 'split' or 'tab'
      width = 40,
      height = 15,
      close_after_jump = true,
      show_labels = false,
      show_includes = true,
      show_todos = true,
    }
<

14. CITATIONS                                                   *nvim-tex-cite*

`:TexCite` (or `<localleader>b`) searches DBLP for a paper and cites it:

1. The query comes from the command line (`:TexCite attention need`) or a
   prompt. Every word has to occur in the title or in an author's name; the
   last word may be the start of one. Titles that contain the query as a
   phrase come first, then the newest papers. Names are matched as DBLP
   spells them: `leißa`, not `leissa`.
2. The results are offered with |vim.ui.select()|; a picker plugin that
   replaces it (Telescope, fzf-lua, snacks, ...) takes over.
3. The key is offered for editing, starting from `leissa2015graph` -- first
   author, year, first word of the title that says something. A key that is
   taken gets a letter appended.
4. The entry is appended to the bibliography and the key is inserted: into
   the braces of the `\cite`, `\parencite`, `\textcite`, ... it is typed in,
   joining the keys already there, or as `\cite{key}` anywhere else. In
   normal mode it goes behind the cursor, or before a `}` under it.

A paper that is already in the bibliography, recognised by its DOI or its
DBLP record, is cited under its existing key and not added again.

The bibliography is the first file named by `\addbibresource` or
`\bibliography` in the main file, else the first `.bib` file under the
project root. A buffer holding it gets the entry; it is written unless it
has unsaved changes of its own.

To start it from insert mode, right after typing `\cite{`: >lua

    vim.keymap.set('i', '<C-x><C-b>', '<Cmd>TexCite<CR>')
<
DBLP's own search and `.bib` export sit behind a JavaScript bot check that
`curl` cannot pass, so nvim-tex asks DBLP's SPARQL endpoint instead and
assembles the BibTeX entry itself, following DBLP's export: UTF-8 names,
`{Braced}` acronyms in titles, `doi`, `url` and, for arXiv papers,
`eprint`.

>lua
    cite = {
      dblp = {
        enabled = true,
        endpoint = 'https://sparql.dblp.org/sparql',
        max_results = 30,
      },
      key = 'short',     -- 'short', 'source' (DBLP:conf/...) or
                         -- function(entry) returning the key
      edit_key = true,   -- offer the key for editing
      curl = 'curl',
      timeout = 20,      -- seconds per request
    }
<
A `key` function gets the entry as a table with `authors`, `editors`,
`year`, `title`, `type`, `doi` and `source_key`.

15. EVENTS                                                    *nvim-tex-events*

The plugin fires |User| autocmds. The `data` table carries `main`, `root` and
`status`; look the project up with
`require('nvim-tex.project').projects[data.main]`.

  NvimTexAttach            the plugin attached to a buffer (`data.bufnr`)
  NvimTexCompileStarted    a compiler job was started
  NvimTexCompileStopped    the compiler job ended
  NvimTexCompileSuccess    a compilation run finished without errors
  NvimTexCompileFailed     a compilation run finished with errors
  NvimTexInverseSearch     the viewer jumped here (`data.file`, `data.line`)

Example: >lua

    vim.api.nvim_create_autocmd('User', {
      pattern = 'NvimTexCompileSuccess',
      callback = function(args)
        vim.notify('built ' .. vim.fn.fnamemodify(args.data.main, ':t'))
      end,
    })
<

16. DIFFERENCES FROM VIMTEX                                   *nvim-tex-vimtex*

nvim-tex is not a fork; it reimplements the parts of VimTeX that are worth
keeping, and drops the rest.

Deliberately different:
  - Lua, Neovim only. No Vimscript, no Vim support.
  - No `l` layer in the leader mappings: `<localleader>l` compiles.
  - Structure comes from tree-sitter, not from a hand written parser or from
    syntax groups. Completion and diagnostics come from texlab, not from an
    omnifunc.
  - Configuration is one nested table passed to `setup`, not a flat namespace
    of `g:` variables.
  - `<plug>` mappings are replaced by commands and the Lua API.

Done differently:
  - Syntax highlighting is tree-sitter's (with nvim-treesitter's query) or
    Neovim's `syntax/tex.vim`; nvim-tex ships no syntax file. Conceal, and
    code highlighting in `lstlisting`, come from the parse tree instead of
    syntax rules. See |nvim-tex-conceal|.
